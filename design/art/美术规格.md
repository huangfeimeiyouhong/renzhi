## 0. 现状诊断（为什么要重做）

| 维度 | 现状 | 问题 | 目标 |
|---|---|---|---|
| 布局 | 顶部状态栏 + 统计徽章行 + 模块卡片流 + 底部 Tab 栏 | 典型的 **后台管理系统信息架构**，孩子看到的是「面板」不是「世界」 | 单一主舞台：一张可滚动的**冒险地图**，Tab 栏降级为悬浮岛 |
| 视觉语言 | 白底卡片 + `box-shadow` + 2px 虚线边框 | 扁平、无纵深、无幻想感 | **微立体 + 厚描边 + 浮空岛**，每个元素都像可以戳的玩具 |
| 反馈 | 颜色变化为主（绿=对 / 红=错） | 无演出感，答对和翻页的体感一样 | 答对有星星迸发、宠物有表情、通关有宝箱 |
| 汉字 | 卡片正面 60px，练习区 84px | 对 5 岁偏小，且是纯黑字无描边 | 主舞台 **120–200px**，带白色厚描边，米字格底衬 |
| 色彩 | `--primary:#FF8A3D` + 白底，整体偏克制 | 色块面积小，饱和度没拉开层次 | 大面积低饱和马卡龙 + 小面积高饱和点缀 |

**关键结论**：不是「换个颜色」的问题，是**从「信息面板」切换到「可游玩的空间」**。

## 1. 视觉身份

### 1.1 一句话风格定义

> **「棉花糖星球」**——一块块飘在奶白色天空里的糖果色浮空岛，圆滚滚的小熊猫陪你一路闯关捡星星。

### 1.2 参考调性（三要素）

| 要素 | 定义 | 工程含义 |
|---|---|---|
| **低饱和马卡龙** | 大面积底色明度 ≥ 88%，饱和度 ≤ 45% | 所有「背景层 / 卡片底 / 场景块」用 L 档色；饱和度靠 HSL 的 S 控制在 30–45% |
| **圆润厚描边** | 所有实体元素带 2.5–4px 深色描边，圆角 ≥ 12px | 描边色 = 该色相的 D 档；**描边是卡通感的来源，不能省** |
| **微立体** | 不是扁平也不是拟物，是「2.5D」：底部一道实心暗边 + 一层柔和投影 | 按钮 `box-shadow: 0 5px 0 <深色>, 0 10px 20px <柔和色>` |

### 1.3 情绪板描述（文字版，供设计对齐）

- **天空**：不是纯蓝，是**奶蓝到奶油白的过渡**（`#BFE7FA → #FFF3E0`），像清晨而非正午，避免高亮刺眼。
- **云**：不是白色几何云，是**圆球堆叠 + 半透明白**（`rgba(255,255,255,.72)`），边缘无描边，缓慢横向漂移。
- **地面/岛屿**：草绿偏**抹茶**（`#8ED46E`），土壤是**焦糖**（`#D9A76C → #B07C46`），不是巧克力，保持轻快。
- **主角**：小熊猫 = **柿子红棕**（`#DE8551`）+ **奶油白脸**（`#FFF1E0`），暖色系，与冷色天空形成对比但不冲突。
- **奖励**：金（`#F2C14E`）+ 粉（`#FF97B4`），只在星星、宝箱、结算弹层出现，**不进入常规界面**。
- **禁止**：纯黑 `#000`、纯白大面积背景 `#FFF`（改用暖白 `#FFFBF5`）、高饱和荧光色、锐角、1px 细线、灰色阴影（`rgba(0,0,0,x)` 一律改为暖褐 `rgba(90,60,40,x)`）。

## 2. 配色系统

### 2.1 三段式明度阶梯（核心机制，务必理解）

低饱和马卡龙与「正文对比度 ≥ 4.5:1」**天然冲突**（实测：白字压在 `#FF8F5A` 上只有 2.25:1）。解决方案是**每个色相拆三档**：

| 档位 | 用途 | 对比度要求 | 说明 |
|---|---|---|---|
| **L（Light）** | 大面积底色、卡片内嵌底、场景色块 | 无需承载文字，仅需与相邻元素有 1.2:1 边界 | 低饱和马卡龙就在这里 |
| **M（Main）** | 按钮填充、进度条填充、图标底板 | 白字需 **≥ 3:1**（按钮文字 19px/800 属 WCAG「大文本」，阈值 3:1） | 中等饱和，是「高饱和点缀色」 |
| **D（Deep）** | 文字、描边、线条 | 需 **≥ 4.5:1**（对 `#FFFFFF` 与 `#FFFBF5`） | 深色调，承载全部可读性 |

> ⚠️ **绝不允许**在 M 档色上写黑色小字、或用 L 档色写任何正文。

## 3. 字体与字号阶梯

### 3.1 字体栈

```css
:root{
  /* 正文：系统优先，PingFang SC 在 iOS/macOS 直接命中 */
  --font-sans: -apple-system, BlinkMacSystemFont, "PingFang SC", "HarmonyOS Sans SC",
               "Source Han Sans SC", "Noto Sans CJK SC", "Microsoft YaHei", sans-serif;

  /* 汉字展示：楷体优先 —— 笔画起收清晰，是小学识字教学的标准字形 */
  --font-hanzi: "Kaiti SC", "STKaiti", "KaiTi", "Kaiti TC", "BiauKai",
                "PingFang SC", "Songti SC", serif;

  /* 拼音/数字：无衬线，避免 Kaiti 下罗马字母变形 */
  --font-latin: -apple-system, BlinkMacSystemFont, "PingFang SC", system-ui, sans-serif;
}
```

> ⚠️ **汉字用楷体是重要决策**：黑体（PingFang）笔画等粗，5 岁儿童难以分辨「日/曰」「人/入」；楷体有笔锋顿挫，是教材标准。全部为系统字体，**零外链**。
> ⚠️ 安卓无 Kaiti，兜底到 PingFang SC / 思源 —— 可接受。

### 6.1 选型理由

| 候选 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **小熊猫** ✅ | 红棕色与暖色调系统一；**环纹尾巴是天然的成长进度条**（环数随阶段增加）；脸谱（白眉+白颊+白吻）辨识度极高；性别中立偏可爱 | 比兔子多 3–4 个图元 | **选用** |
| 小兔子 | 最好画 | 长白耳朵占竖向空间，小屏不友好；形象过于常见 | 备选 |

> **关键技巧 1 — 脸谱用 `clipPath`**：白眉 / 白颊 / 白吻画在 `<g clip-path="url(#headClipN)">` 里，超出头圆的自动裁掉，得到干净的「面具」边缘，不需要手算边界。
> **关键技巧 2 — 尾巴用 `stroke-dasharray`**：同一条 `path` 画两遍，第二遍用 `stroke-dasharray` 出环纹。**改环数 = 改 dasharray 数字**，这就是「尾巴环数 = 成长进度」的实现方式。

### 8.3 `prefers-reduced-motion` 降级（**必须实现**）

```css
:root{
  --dur-tap:120ms; --dur-std:240ms; --dur-emp:400ms; --dur-show:800ms;
  --ease-tap: cubic-bezier(.34,1.56,.64,1);
  --ease-std: cubic-bezier(.4,0,.2,1);
  --ease-emp: cubic-bezier(.16,1,.3,1);
  --ease-show:cubic-bezier(.22,1.2,.36,1);
  --ease-soft: cubic-bezier(.45,0,.55,1);   /* 循环动效专用，起止平滑无跳变 */
}

/* ✅ 全局降级：所有动画/过渡压缩到近乎瞬时，但保留必要的位置变化（避免内容"瞬移"丢失上下文） */
@media (prefers-reduced-motion: reduce){
  *, *::before, *::after{
    animation-duration: .001ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: .001ms !important;
    scroll-behavior: auto !important;
  }
  /* 常驻循环动画必须彻底关闭（只压缩时长会让它以 .001ms 疯狂闪烁） */
  .pet-tail, .pet-body, .pet-head, .pet-ear, .pet-tear,
  .cloud, .leaf, .mapnode.is-open .art, .mapnode.is-active .art,
  .mapnode.is-perfect .rays, .chest.is-ready .chest-body,
  .bar__fill::after{
    animation: none !important;
  }
  /* 一次性演出动画：保留"结果态"，去掉"过程" */
  .chest.is-open .chest-lid{ transform: rotate(-34deg) translateY(-3px); }
  .overlay.show .modal{ transform:none; opacity:1; }
  .toast{ transition: opacity 120ms linear; }
  /* 保留必要的状态反馈（颜色/边框），不依赖动画传达信息 */
  .opt.right{ background:#DDF5E9; border-color:#2FA373; }
}
```

> ⚠️ **只写 `animation-duration:.001ms` 是不够的**：循环动画（`infinite`）被压缩后会在每帧重启动画，表现为高速闪烁，**对光敏感儿童是风险**。上面第二条规则逐个关闭循环动画，是必须的。
> ⚠️ **不要用动画单独传达信息**：答对/答错必须同时有颜色 + 图标 + 文字变化，`prefers-reduced-motion` 下动画消失后信息不能丢失。

## 9. 音效音色建议（Web Audio API 合成）

### 9.1 设计原则（护耳）

| 原则 | 参数 |
|---|---|
| **波形** | 只用 `sine` 与 `triangle`（谐波少、柔和）；**禁用 `square` / `sawtooth` 直接输出** |
| **峰值频段** | 基频控制在 **300–1600 Hz**，避开 2–4 kHz（人耳最敏感区，也是听觉损伤高危区） |
| **总音量** | master gain **≤ 0.5**，单音 peak **≤ 0.16** |
| **低通滤波** | 全局 `lowpass @ 5200 Hz, Q=0.7`，削掉刺耳高频 |
| **起振时间** | attack **≥ 10ms**（瞬间的 click 声比持续音更伤耳） |
| **包络** | 指数衰减 `exponentialRampToValueAtTime`，不用线性，听感自然 |
| **总时长** | 单音效 **≤ 800ms**，不拖尾 |

### 9.2 完整合成代码（已通过 `node --check`）

```js
/* ============ SFX：Web Audio 合成音效（零外链） ============ */
var SFX = (function(){
  var AC=null, MASTER=null, LP=null, enabled=true;

  function ctx(){
    if(!AC){
      var C = window.AudioContext || window.webkitAudioContext;
      if(!C) return null;
      AC = new C();
      LP = AC.createBiquadFilter(); LP.type='lowpass'; LP.frequency.value=5200; LP.Q.value=.7;
      MASTER = AC.createGain(); MASTER.gain.value=.5;
      LP.connect(MASTER); MASTER.connect(AC.destination);
    }
    if(AC.state === 'suspended') AC.resume();   /* iOS 需用户手势解锁 */
    return AC;
  }

  function tone(o){
    if(!enabled) return;
    var c = ctx(); if(!c) return;
    var dur = o.dur||.18, t0 = c.currentTime + (o.delay||0), peak = (o.gain==null?.16:o.gain);
    var osc = c.createOscillator(), g = c.createGain();
    osc.type = o.type || 'sine';
    osc.frequency.setValueAtTime(o.freq, t0);
    if(o.slideTo) osc.frequency.exponentialRampToValueAtTime(o.slideTo, t0 + dur*.9);
    g.gain.setValueAtTime(.0001, t0);
    g.gain.exponentialRampToValueAtTime(peak, t0 + (o.attack||.014));
    g.gain.exponentialRampToValueAtTime(.0001, t0 + dur);
    osc.connect(g); g.connect(LP);
    osc.start(t0); osc.stop(t0 + dur + .06);
  }

  function noise(dur, gain, freq){          /* 低频"隆隆"，仅用于开箱 */
    if(!enabled) return;
    var c = ctx(); if(!c) return;
    var n = Math.floor(c.sampleRate*dur), buf = c.createBuffer(1,n,c.sampleRate), d = buf.getChannelData(0);
    for(var i=0;i<n;i++) d[i] = (Math.random()*2-1) * (1 - i/n);
    var src = c.createBufferSource(); src.buffer = buf;
    var bp = c.createBiquadFilter(); bp.type='lowpass'; bp.frequency.value = freq||500;
    var g = c.createGain(); g.gain.value = gain||.07;
    src.connect(bp); bp.connect(g); g.connect(LP); src.start();
  }

  return {
    setEnabled: function(v){ enabled = !!v; },
    unlock: function(){ ctx(); },            /* 在首次 touchend / click 里调用 */

    /* ① 点击：极短促的软"叮"，880Hz / 70ms */
    tap: function(){ tone({freq:880, dur:.07, type:'sine', gain:.10, attack:.006}); },

    /* ② 答对：C5-E5-G5 上行大三和弦琶音，triangle，每音间隔 85ms */
    right: function(){ [523.25,659.25,783.99].forEach(function(f,i){
      tone({freq:f, dur:.16, type:'triangle', gain:.15, delay:i*.085}); }); },

    /* ③ 答错：G4→D#4 下行小三度 + 滑音，sine，柔和无攻击性 */
    wrong: function(){ tone({freq:392, slideTo:311, dur:.26, type:'sine', gain:.13, attack:.02}); },

    /* ④ 通关：C5-E5-G5-C6 四音琶音 + 尾部 G6 长铃音 */
    clear: function(){
      [523.25,659.25,783.99,1046.5].forEach(function(f,i){
        tone({freq:f, dur:.22, type:'triangle', gain:.14, delay:i*.11}); });
      tone({freq:1567.98, dur:.5, type:'sine', gain:.07, delay:.42}); },

    /* ⑤ 升级：五音上行 + 尾部双音持续和声 */
    levelup: function(){
      [523.25,659.25,783.99,1046.5,1318.5].forEach(function(f,i){
        tone({freq:f, dur:.18, type:'triangle', gain:.14, delay:i*.1}); });
      tone({freq:1046.5,  dur:.7, type:'sine', gain:.10, delay:.5});
      tone({freq:1567.98, dur:.7, type:'sine', gain:.06, delay:.5}); },

    /* ⑥ 开箱：低频隆隆 + 660→1318Hz 上滑 + 双层铃音 */
    chest: function(){
      noise(.22,.06,380);
      tone({freq:660, slideTo:1318.5, dur:.34, type:'sine', gain:.13, attack:.03});
      tone({freq:1760, dur:.45, type:'sine', gain:.08, delay:.2});
      tone({freq:2093, dur:.40, type:'sine', gain:.05, delay:.26}); }
  };
})();

/* 首次用户手势解锁音频（iOS Safari 必需） */
document.addEventListener('touchend', function once(){ SFX.unlock(); document.removeEventListener('touchend', once); }, {passive:true});
document.addEventListener('click',    function once(){ SFX.unlock(); document.removeEventListener('click',    once); });
```

### 9.3 参数速查表

| 事件 | 波形 | 频率 (Hz) | 时长 | 间隔 | 峰值 gain | 音色描述 |
|---|---|---|---|---|---|---|
| 点击 tap | sine | 880 | 70ms | — | .10 | 软「叮」，像轻触风铃 |
| 答对 right | triangle | 523.25 / 659.25 / 783.99 | 160ms×3 | 85ms | .15 | 明亮上行琶音，有「对了！」的肯定感 |
| 答错 wrong | sine（滑音） | 392 → 311 | 260ms | — | .13 | 柔和下行，「哎呀」而非「错误」 |
| 通关 clear | triangle + sine | 523/659/784/1047 + 1568 | 220ms×4 + 500ms | 110ms | .14 / .07 | 四音上行 + 清亮铃尾 |
| 升级 levelup | triangle + sine | 523/659/784/1047/1319 + 1047&1568 持续 | 180ms×5 + 700ms | 100ms | .14 / .10 / .06 | 五音阶梯 + 和声尾音，最有仪式感 |
| 开箱 chest | noise(lowpass 380) + sine 滑音 | 660→1318 + 1760 + 2093 | 220/340/450/400ms | 0/0/200/260ms | .06/.13/.08/.05 | 木箱「隆隆」+ 魔法上滑 + 星光 |

> 🔧 **家长面板必须提供「关闭音效」开关**（默认开启），并在 `localStorage` 持久化：`SFX.setEnabled(false)`。

## 10. 可访问性清单

### 10.1 触控与误触

| 项 | 要求 | 本方案值 |
|---|---|---|

| 危险操作二次确认 | 「清空进度」「重置」必须二次确认 | 用 `--c-err` 危险按钮 + 确认弹层 |
| 家长面板入口 | 需防误触 | 长按 1.5s 或连续点击 5 次 logo，**不放主界面显眼处** |

| 滑动冲突 | 地图横向不可滑，纵向可滑 | `overflow-x:hidden; overflow-y:auto` |

### 10.2 色彩对比

- 正文文字 **≥ 4.5:1**（本方案最低 5.33:1，实测见 §2.7）
- 按钮大文本（19px / 800）**≥ 3:1**（本方案最低 3.06:1）
- 图形元素边界 **≥ 3:1**（靠描边色达标，填充色不受限）
- **不得仅用颜色区分状态**：每态必须叠加图标（✓ / ✗ / 🔒 / ★）或文字
- 禁用态**不用 `opacity`** 降低，改用固定低对比配色（`#F0E9E0` / `#9C8878`，3.32:1）

### 10.3 动效降级

- 完整实现 `prefers-reduced-motion: reduce`（见 §8.3）
- **循环动画必须 `animation:none`**，不能只压缩时长
- 不依赖动画单独传达信息（颜色 + 图标 + 文字三冗余）
- 无自动播放的背景音乐；音效可通过家长面板关闭

### 14.1 🔴 必修 · 地图 viewBox 高度溢出

**问题**：GDD §2.3 写 `viewBox="0 0 400 2400"`，但按 §2.3 的 `nodePos` 公式：

### 14.3 🔴 必修 · 节点触控圈过小（小屏不达标）

**问题**：GDD §11.1 要求 `--tap-min:64px`，但节点视觉半径 `r=34`。在 **360px 宽**的安卓机上：

```
缩放比 = 360 / 400 = 0.90
节点直径 = 34 × 2 × 0.90 = 61.2px  ＜  64px  ❌
```

**修正**：**视觉半径与触控半径解耦**——视觉仍 `r=34`（Boss `r=44`），但叠加一个 `r=48` 的透明触控圈：

```
触控直径 = 48 × 2 × 0.90 = 86.4px  ✅（360px 屏）
触控直径 = 48 × 2 × 0.975 = 93.6px ✅（390px 屏）
```

触控圈放在节点 `<g>` 的**最后一个子元素**，保证命中优先级。见 §17。

design-strategist 复核后**全额接受** 39.6 KB，三项压缩方案**全部驳回**：

| 压缩方案 | 节省 | 裁决 | 理由 |
|---|---|---|---|
| 剥离注释与空行 | −4 KB | ❌ **驳回** | 这是 Phil 要长期手工维护的单文件项目（调宠物数值、加汉字、改奖励），注释的可维护性远超 4 KB（占总量 2.9%）。本地单文件加载无差异，gzip 那点收益没意义 |

## 15. 宠物 · 字灵「墨墨」

### 15.1 选型与造型定义

> **一句话**：一颗会呼吸的墨点，长着两只尖耳朵，是孩子学过的字变的。

**造型语言**（延续 §1.2 的「低饱和马卡龙 + 圆润厚描边 + 微立体」）：

| 要素 | 规格 |
|---|---|
| 轮廓 | 头身一体的**圆润水滴**（不是分段身体），`ellipse rx=32 ry=33` |
| 耳朵 | 两只**细长尖耳**（`ellipse rx=8.5 ry=17` 旋转 ±24°）——这是「精灵感」的来源 |
| 墨尾 | 右下一条粗描边曲线（先描边后填色做出轮廓），呼应「墨」的主题 |
| 脸 | 大眼（`r=6~7`）+ 高光 + 大面积腮红，`opacity .5` |
| 描边 | 2.6px（Lv5 升级为 3px 金色 `#FFC93C`） |
| 微立体 | 径向渐变（左上亮 `#hi` → 右下暗 `#theme`）+ 底部投影 |

**为什么是「墨点」而不是动物**：宠物是孩子学过的字变的（GDD §5.1），所以 Lv5 时它身边环绕的 5 颗小字灵**显示孩子已掌握的汉字**——这是整个 App 里唯一一处「学习成果实体化」的时刻，也是留存钩子的视觉落点。

### 16.3 节点坐标公式（蛇形两列）

- `x` 只在 `110` / `290` 两列之间摆，形成蛇形；列间距 `180`，节点直径最大 `88`（Boss），两列不会重叠。

### 17.1 状态总表

| state | 半径 | 主体填充 | 附加元素 | 动画 |
|---|---|---|---|---|
| `locked` | 34 / Boss 44 | `#C9C2B8` 灰 | 🔒 锁 + 3 朵白云 | 云横向漂移 4s 循环；整区 `saturate(.25) brightness(.9)` |

**Boss 关**（`i%5===4`）：`R=44`，外挂 8 角星框（`R+13` / 内半径 `R+4`），`rotate 20s` 匀速旋转。

> ✅ **推进阶段：全图同时最多只有 1 个"活跃"节点**。`available` 与 `inProgress` 互斥（同一个 `currentLevelIdx()` 上按 `sections` 是否为 0 二选一），所以**光环 + 小旗 + 浮动**这三样动效在同一时刻只出现在一个节点上。
>
> 同理，底部小节圆点（`inProgress`）也只会同时出现在一个节点上——重玩旧关中途退出不算 `inProgress`，节点保持 `cleared`（GDD §2.4）。

> ⚠️ **但"动效节点数恒为 1"只在推进阶段成立，终局会翻车。** 全通关时 `available`/`inProgress` 归零，但 20 个节点全部变成 `perfect` —— 而 `perfect` 是**有**动画的（`perfectflash` 3s + `crownbob` 2.4s）：
>
> | 阶段 | `available`/`inProgress` | `cleared` | `perfect` | 同时运行的动画 |
> |---|---|---|---|---|
> | 初期（通关 3 关） | 1 | 3 | 0 | **2 个**（光环+浮动，同一节点） |
> | 中期（通关 12 关） | 1 | 12 | 0 | **2 个** ✅ |
> | 终局（20 关全三星） | 0 | 0 | **20** | **40 个** ❌ |
>
> 终局是**最吵的状态**，而它恰恰是孩子待得最久的状态（全部打完之后地图就是终点页）。修法见 §17.7。

> ⚠️ **`perfect` 是 `cleared` 的子集，不是并列状态。** 判定唯一入口是 `lv.stars >= 3`：
> - `cleared` 且 `stars` 为 1–2 → state 传 `cleared`，3 个星位、亮 1–2 颗、**无金边无皇冠、全部动画关闭**
> - `cleared` 且 `stars === 3` → state 传 `perfect`，3 颗全亮 + 金边 4px + 皇冠
>
> 也就是说 `cleared` 状态下**永远只亮 1–2 颗**，不会出现"cleared 但亮 3 颗"的情况——亮 3 颗就该走 `perfect`。工程师不要在 `cleared` 分支里判断 `stars===3`。

### 17.4 状态切换的调用示例

> ⚠️ **数据形状以 GDD §12.2 为准**：唯一权威数据源是 `state.game.levels["L1".."L20"]`（**对象，key 带 L 前缀**），字段为
> `{stars:0..3, cleared:bool, plays:n, best:n, firstClearAt:ts, sections:0..3}`。
> 本规格早期版本用过 `save.levels[i]`（数组）+ `save.current` + `lv.sub` + `lv.perfect` 的临时形状，**已作废，不要使用**。
>
> `nodeSVG(i, st)` 的 `st` 需要 `{state, stars, sub, total}`，用 GDD §2.4 的 `nodeRenderState()` 归一化后补两个字段即可。

```js
/* ---- 以下两个函数均为只读引用，权威定义在 GDD §2.4 ---- */

/* ⚠️ currentLevelIdx 是【函数】不是变量，别漏括号。
   它不落盘，由 recalcZones(s) 派生的 unlockedThrough 算出来；
   终局 unlockedThrough=20 → 返回 19（L20），命中 cleared/perfect 分支，不会越界。 */
function currentLevelIdx(){
  return Math.min(19, Math.max(0, (state.game.unlockedThrough|0) - 1));
}

function nodeRenderState(levelIndex){
  var lv = state.game.levels["L"+(levelIndex+1)] || {};
  if(lv.cleared && (lv.stars|0) >= 3) return {state:"perfect",    stars:3,           sections:3};
  if(lv.cleared)                      return {state:"cleared",    stars:lv.stars||1, sections:3};
  if(levelIndex === currentLevelIdx()){
    var sec = lv.sections || 0;
    return {state: sec>0 ? "inProgress" : "available", stars:0, sections:sec};
  }
  return {state:"locked", stars:0, sections:0};
}

/* ---- 美术层：归一化结果 → nodeSVG 入参 ---- */
function renderMap(){
  var states = [], i, r;
  for(i=0;i<20;i++){
    r = nodeRenderState(i);
    states.push({
      state: r.state,
      stars: r.stars,
      sub:   r.sections,     /* GDD 叫 sections，nodeSVG 内部叫 sub */
      total: 3
    });
  }
  document.getElementById('mapHost').innerHTML = mapSVG(states);
}

/* ---- 首次进入自动滚到当前关（等 mapSVG 插入 DOM 之后再调） ---- */
function scrollToCurrent(){
  var wrap  = document.querySelector('.map-wrap');
  var p     = nodePos(currentLevelIdx());
  var scale = wrap.clientWidth / 400;            /* MAP_W = 400 */
  wrap.scrollTop = Math.max(0, p.y * scale - wrap.clientHeight / 2);
}
```

**字段对照表**（两套命名只在这一行做转换，不要扩散到别处）：

| GDD §12.2 | `nodeRenderState()` 输出 | `nodeSVG()` 入参 | 说明 |
|---|---|---|---|
| `levels["L"+(i+1)]`（对象） | — | `i`（索引 0–19） | key 带 `L` 前缀，索引从 1 起 |
| `lv.stars` | `stars` | `stars` | 一致，无需转换 |
| `lv.cleared` + `stars>=3` | `state:"perfect"` | `state` | **派生**，GDD 无 `perfect` 字段 |
| `lv.sections`（0–3） | `sections` | `sub` | **改名点**，仅此处 |
| `unlockedThrough` | `currentLevelIdx()`（**函数**） | — | GDD 无 `current` 字段；定义见 GDD §2.4 |
| `sections > 0` | `state:"inProgress"` | `state` | 仅当前推进关；**重玩旧关中途退出不算** |

> **全量重绘，不做增量**。20 个节点重建一次约 3ms，比维护 20 个节点的增量 diff 简单且不容易出状态残留 bug。滚动时**不要**重绘。
>
> **两个边界**（GDD §2.4 定义，影响视觉密度）：
> - **全通关时** `unlockedThrough=20` → `currentLevelIdx()=19` → L20 命中 `cleared`/`perfect`，`scrollToCurrent()` 仍有正确落点，不会滚到空白。
> - **重玩旧关中途退出不显示为 `inProgress`**，节点保持 `cleared`。地图只呈现永久成就。

### 17.7 ⚠️ 终局噪声修正（v2.2 新增）

**问题**：终局 20 个节点全是 `perfect`，每个都在跑 `perfectflash` + `crownbob`，且因为同一时刻渲染，**全部同相位**——20 个金环同步闪、20 个皇冠同步上下，整张图像在抽搐。同时 20 个 `drop-shadow` 滤镜层在滚动时会拖慢移动端帧率。

**三处修正**：

**① 相位打散** —— 给节点 `<g>` 注入索引，用负延迟错开：

```js
/* nodeSVG 中，最外层 <g> 加 style="--i:N" */
var g = '<g class="node n-'+st.state+(boss?' n-boss':'')+'" '+
        'transform="translate('+p.x+','+p.y+')" style="--i:'+i+'" '+
        'data-lv="'+(i+1)+'" data-page-node-id="mapnode-L'+(i+1)+'" ...>';
```

```css
.n-perfect .disc{
  transform-box:fill-box; transform-origin:center;
  animation:perfectflash 3s ease-in-out infinite;
  animation-delay:calc(var(--i,0) * -137ms);   /* 互质步长，20 个节点不撞相位 */
}
.n-perfect .crown{
  transform-box:fill-box; transform-origin:center;
  animation:crownbob 2.4s ease-in-out infinite;
  animation-delay:calc(var(--i,0) * -211ms);   /* 与 flash 用不同步长，避免两组同步 */
}
.n-boss .bossframe{
  transform-box:fill-box; transform-origin:center;
  animation:bossspin 20s linear infinite;
  animation-delay:calc(var(--i,0) * -1000ms);  /* 4 个 Boss 星框也错开 */
}
```

> 步长取 **137 / 211**（互质且远大于 20），保证任意两个节点的相位差都不同。用负延迟而不是正延迟，是为了**首帧就有动画**，不用等。

**② `drop-shadow` 换成双层描边** —— 20 个 filter 层在移动端滚动时掉帧，改用零成本的双描边模拟发光：

```js
/* nodeSVG 中，perfectring 改成两道同心描边 */
if(st.state==='perfect')
  g += '<circle class="perfectring-glow" r="'+(R-4)+'" fill="none" stroke="#FFD86B" '+
       'stroke-width="10" opacity=".28"/>'+
       '<circle class="perfectring" r="'+(R-4)+'" fill="none" stroke="#FFC93C" stroke-width="4"/>';
```

```css
/* 删掉原来的 filter:drop-shadow(...) */
.n-perfect .perfectring-glow{ pointer-events:none; }
```

> `drop-shadow` 是 SVG filter，每个实例一次离屏渲染；两道 `stroke` 只是多画一圈，成本差一个数量级。视觉上「宽而淡的外圈 + 窄而实的内圈」比模糊滤镜更接近贴纸质感，也更符合 §1 的视觉身份。

**③ 终局额外降级（OPTIONAL · 默认关闭）**

> ❌ **默认不启用。** §17.6 里那条 `.n-perfect:not(.n-current) .crown{ animation:none; }` 是**注释掉的**，工程照抄 §17.6 不会拿到它。
> 这一条只在**真机实测确认终局仍然吵**时才打开，且打开前必须先确认 §17.4 的 `renderMap()` 确实给 L20 加了 `.n-current`。

如果实测还是吵，才加这一条：非当前关的 `perfect` 节点关掉皇冠浮动，只保留 3s 一次的闪烁。

```css
/* ⚠️ 默认关闭。启用前先确认 .n-current 已正确注入，否则 20 个皇冠会全灭。 */
/* .n-perfect:not(.n-current) .crown{ animation:none; } */
```

**`.n-current` 权威定义**（GDD §16 给出，此处复述以便美术层对齐）：

| 项 | 规则 |
|---|---|
| 谁加 | `renderMap()` |
| 加在哪 | `currentLevelIdx()` 对应的那个节点 |
| 条件 | **无条件**。无论该节点是 `locked` / `available` / `inProgress` / `cleared` / `perfect`，一律加 |
| 终局取值 | `currentLevelIdx() = 19` → **L20 带 `.n-current`**，即使它是 `perfect` |

> 这条最容易踩的坑：因为终局时当前关**就是**一个 `perfect` 节点，任何「排除非当前关的 perfect」的写法都会把唯一的当前关也排除掉。所以判定必须写成 `currentLevelIdx() === i` 的正向条件，不能用 `:not(.n-current)` 反向排除。

**修正后的终局动效密度**：

| 项 | 修正前 | 修正后 |
|---|---|---|
| 同时运行的 CSS 动画 | 40 个 | 40 个（数量不变，但**相位错开**） |
| SVG filter 层 | **20 个** | **0 个** ✅ |
| 视觉感受 | 20 个金环同步抽搐 | 零星点缀，像星星眨眼 |

### 18.1 三种货币图标规格

| 货币 | 造型 | 主色 | 描边 | 尺寸 | 对比度（vs 白） |
|---|---|---|---|---|---|
| ⭐ 星星 | 5 角星（外 13 / 内 5.6） | `#FFC93C` | `#B87400` 2.2 | 24 / 32 | 3.79 ✅ 图形 ≥3 |

**设计要点**：

- **能量果不用 emoji 🍎**。emoji 在不同系统渲染差异极大（iOS 是红苹果，部分 Android 是青苹果），且无法保证单文件零外链下的一致性。这里用路径画：苹果体 `C` 曲线 + 棕色果柄 + 一片 `#8ED46E` 叶子。
- **钥匙碎片用 `stroke-dasharray`**：`r=10.5` 的圆，`stroke-width=6`，`dasharray="14 8"`，`rotate(-90 16 16)` 让缺口从正上方开始。圆周长 = 2π×10.5 ≈ 65.97，`14+8=22`，65.97/22 ≈ 3.0 → 正好 **3 段等分缺口**。这个 22 是算出来的，不要随手改；改半径就要重算。
- **完整钥匙**是碎片集齐后的合并态，色号用金色（升格感），与"碎片"的紫色明确区分。

### 18.3 五通道冗余表（对错反馈）

GDD 要求"红绿不能是唯一区分维度"。本规格给出 **5 条独立通道**，任意一条单独成立都能判断对错：

| # | 通道 | 答对 | 答错 | 备注 |
|---|---|---|---|---|
| 1 | **颜色** | 绿 `#0F6B3E` | 红 `#C62828` | 圆底填充，白勾/叉对比度 6.58 / 5.62 ✅ |
| 2 | **形状** | ✓ 勾（折线） | ✗ 叉（两直线交叉） | 形状差异在灰度下依然成立 |
| 3 | **声音** | 上扬两音 `C5→E5` | 下沉两音 `G4→E4` | 见 §9，音高方向是硬区分 |
| 4 | **动效** | 弹入放大 `scale(.4→1.12→1)` | **左右抖动** `translateX ±8px` | 方向相反，余光可辨 |
| 5 | **文字** | 卡片显示"答对啦！" | 卡片显示"再想想～" | 最直白的一层 |

**额外**：答错时**整张卡片也抖**（`.shake`），这是第 4 通道的加强版，利用的是"大面积位移"比"小图标位移"更容易被余光捕捉。

**灰度自测方法**：把设备开成"色彩滤镜 → 全色盲"（iOS 辅助功能），只看形状 + 抖动就能判断对错 = 通过。

```css
}

  15%{ transform:translateX(-7px) rotate(-3deg); }
```

**三条硬规则**：

1. `.shake` 用 **`animation`** 而不是 `transition`——抖动需要往返，`animation` 才能一次跑完自动归位。
2. 抖动幅度 **±8px 是上限**。再大在 iPad 横向握持时会有明显的"甩动感"，5 岁孩子容易被吓到或误以为屏幕坏了。
3. 一次答题**只播一次**抖动。连错时要先 `el.classList.remove('shake'); void el.offsetWidth; el.classList.add('shake')` 强制重排，否则第二次不触发。

### 19.3 分层与开箱动画

**四层结构**（z-index 从低到高）：

```
0  .c-glow   柔光晕（radial-gradient，scale .4 → 1）
1  .c-base   箱底座（含 SVG）
2  .c-prize  奖品（初始藏在底座后，开启时向上浮出）
   .c-beam   光柱（height 0 → 160px）
3  .c-lid    箱盖（rotateX 0 → -70deg）
```

> **`.c-beam` 和 `.c-prize` 同在 z-index:2**，靠 DOM 顺序区分（beam 在前，prize 在后 → prize 盖在 beam 上，视觉上是"奖品从光柱里升起"）。

**开箱时序**（总时长 1.1s）：

| t | 事件 | 属性 |
|---|---|---|
| 0 ms | 加 `.is-open` | — |
| 200 ms | 光柱升起 | `.c-beam{height:0→160px}` .5s，delay .2s |
| 200 ms | 柔光亮起 | `.c-glow{scale .4→1, opacity 0→1}` .6s |
| 200 ms | 箱盖掀起 | `.c-lid{rotateX(0→-70deg)}` .62s，`cubic-bezier(.34,1.3,.5,1)` 带轻微回弹 |
| 460 ms | 奖品浮出 | `.c-prize{translateY(14→-16px), scale .8→1, opacity 0→1}` .5s，delay .26s |
| 460 ms | 撒星星粒子 | `starBurstSVG()` 8 颗 |
| 1100 ms | 动画结束 | — |

**关键 CSS 细节**：

```css
.chest3d{
  position:relative; width:200px; height:190px; margin:0 auto;
  perspective:600px;                    /* 必须，否则 rotateX 没有透视 */
  perspective-origin:50% 34%;           /* 视点略高于箱盖，掀开时更有"仰视"感 */
}
.c-lid{
  position:absolute; left:0; right:0; bottom:104px; height:82px; z-index:3;
  transform-origin:bottom center;       /* 绕自己底边掀，不是绕中心 */
  transform-style:preserve-3d;
  transform:rotateX(0deg);
  transition:transform .62s cubic-bezier(.34,1.3,.5,1);
}
.chest3d.is-open .c-lid{ transform:rotateX(-70deg); }
```

> **三个最容易写错的地方**：① 忘了 `perspective` → 掀盖变成"压扁"；② `transform-origin` 写成 `center` → 盖子绕中心转，一半沉进箱子；③ 用 `-70deg` 但父级没有 `perspective-origin` 调整 → 透视角度太平，看不出立体。

## 20. 复用特效件库

> 对应 GDD §16 第 7 项 + §8.3 性能约束 + §11.7 动效降级。

### 20.1 两条硬约束

| 约束 | 实现 |
|---|---|
| **同屏粒子 ≤ 24** | 全局计数器 `fxLive` + 闸门 `fxSpawn(n)`。超限时**直接放弃生成**（返回 `false`），不排队、不降帧 |
| **`prefers-reduced-motion` 下禁位移/缩放** | CSS 层：所有 `infinite` 循环 `animation:none`；一次性动画重写关键帧，只保留 `opacity` |

**粒子配额分配建议**（避免两个特效同时播时互相挤掉）：

| 特效 | 单次粒子数 | 建议并发 |
|---|---|---|
| 彩带 `confetti` | 18 | 独占（配合 6 颗星 = 24） |
| 星星粒子 `starBurst` | 8 | 可 3 组同时（24） |
| 光环 `halo` | 1（不算粒子） | 不限 |
| 碎片 `shards` | 8 | 可 3 组同时（24） |

### 20.2 四个特效件

| 件 | 函数 | 参数 | 组成 |
|---|---|---|---|
| 彩带 | `confettiSVG(n,w,h)` | `n≤24`，`w/h` 容器尺寸 | 8×14 圆角矩形（`rx=3`），6 色循环，随机 `x` / 旋转 / 时长 / 延迟 / 横向偏移 |
| 星星粒子 | `starBurstSVG(cx,cy,R,n)` | `R` 放射半径默认 46，`n` 默认 8 | 8 颗 5 角星沿圆周均匀分布，从中心炸开 |
| 光环 | `haloSVG(cx,cy,r0,r1,color)` | `r0` 起始半径，`r1` 结束半径 | 单个圆，`scale(r1/r0)` 扩张 + `stroke-width 9→1` + 淡出 |
| 碎片 | `shardsSVG(cx,cy,n)` | `n` 默认 8 | 8 片菱形（`M0 -8 L6 0 L0 8 L-6 0 Z`），旋转 + 外飞 + 缩小 |

**彩带配色**（已把最浅的两色加深，避免在浅色背景上糊掉）：

```js
var FX_COLORS = ['#E23C74','#FFC93C','#3DA5E0','#6FCB8F','#9B6DFF','#E5680F'];
```

| 色 | 原值 / 比值 | 修正 / 比值 |
|---|---|---|
| 粉 | `#FF6B9D` 2.68 | **`#E23C74` 4.09** ✅ |
| 橙 | `#FF8A3D` 2.35 | **`#E5680F` 3.32** ✅ |

**固定种子伪随机**：`fxReset(20260830)` 在每次生成前重置，保证同一次奖励的彩带分布可复现（不会出现"重进页面彩带位置全变了"的廉价感）。

### 20.3 特效件代码

```js
/* ===================== §20 复用特效件库 ===================== */
/* 硬约束：单屏同屏粒子总数 <= 24；prefers-reduced-motion 下禁位移/缩放，只留颜色变化 */

var FX_COLORS = ['#E23C74','#FFC93C','#3DA5E0','#6FCB8F','#9B6DFF','#E5680F'];
var FX_MAX = 24;               /* 同屏粒子上限 */
var fxLive = 0;                /* 当前存活粒子数 */

/* 计数闸门：超上限就直接放弃，绝不排队堆积 */
function fxSpawn(n){ if (fxLive + n > FX_MAX) return 0; fxLive += n; return 1; }
function fxKill(n){ fxLive = Math.max(0, fxLive - n); }

/* 固定种子伪随机：同一次奖励的彩带分布可复现 */
var fxSeed = 1;
function fxRnd(){ fxSeed = (fxSeed*1103515245 + 12345) & 0x7fffffff; return fxSeed/0x7fffffff; }
function fxReset(seed){ fxSeed = seed || 1; }

/* --- 1. 彩带：8x14 圆角矩形，6 色循环 --- */
function confettiSVG(n, w, h){
  n = Math.min(n||18, FX_MAX);
  w = w||360; h = h||300;
  fxReset(20260830);
  var o = '<svg class="fx fx-confetti" viewBox="0 0 '+w+' '+h+'" '+
          'preserveAspectRatio="none" xmlns="http://www.w3.org/2000/svg" aria-hidden="true">', i;
  for(i=0;i<n;i++){
    var x   = (fxRnd()*w).toFixed(1);
    var y   = (-20 - fxRnd()*60).toFixed(1);
    var c   = FX_COLORS[i % 6];
    var rot = (fxRnd()*360).toFixed(0);
    var dur = (1400 + fxRnd()*900).toFixed(0);
    var dly = (fxRnd()*420).toFixed(0);
    var dx  = ((fxRnd()*2-1)*40).toFixed(1);
    o += '<rect class="cf" x="'+x+'" y="'+y+'" width="8" height="14" rx="3" fill="'+c+'" '+
         'style="--dx:'+dx+'px;--rot:'+rot+'deg;--dur:'+dur+'ms;--dly:'+dly+'ms"/>';
  }
  return o + '</svg>';
}

/* --- 2. 星星粒子：8 颗一组放射 --- */
function starBurstSVG(cx, cy, R, n){
  n = n || 8; R = R || 46;
  var o = '<g class="fx fx-starburst" aria-hidden="true">', i, ang, tx, ty;
  for(i=0;i<n;i++){
    ang = (Math.PI*2/n)*i - Math.PI/2;
    tx = (Math.cos(ang)*R).toFixed(1);
    ty = (Math.sin(ang)*R).toFixed(1);
    o += '<g class="sp" style="--dx:'+tx+'px;--dy:'+ty+'px;--dly:'+(i*40)+'ms">'+
         '<path d="M0 -7 l2 4.2 4.6 .7 -3.3 3.2 .8 4.6L0 2.6l-4.1 2.1 .8-4.6L-6.6 -2.1 l4.6-.7z" '+
         'transform="translate('+cx+','+cy+')" fill="#FFC93C" stroke="#B87400" stroke-width="1.4" '+
         'stroke-linejoin="round"/></g>';
  }
  return o + '</g>';
}

/* --- 3. 光环：向外扩张的圆（缩放系数在 JS 里算好，不丢给 CSS calc） --- */
function haloSVG(cx, cy, r0, r1, color){
  r0 = r0 || 10; r1 = r1 || 70;
  var s = (r1 / r0).toFixed(3);
  return '<circle class="fx fx-halo" cx="'+cx+'" cy="'+cy+'" r="'+r0+'" '+
         'fill="none" stroke="'+(color||'#FFC93C')+'" stroke-width="6" '+
         'style="--s:'+s+'" aria-hidden="true"/>';
}

/* --- 4. 碎片：8 片爆散（拍字地鼠打中） --- */
function shardsSVG(cx, cy, n){
  n = n || 8;
  var o = '<g class="fx fx-shards" aria-hidden="true">', i, ang, tx, ty, rot;
  for(i=0;i<n;i++){
    ang = (Math.PI*2/n)*i;
    tx = (Math.cos(ang)*54).toFixed(1);
    ty = (Math.sin(ang)*54).toFixed(1);
    rot = (i*47).toFixed(0);
    o += '<path class="sh" d="M0 -8 L6 0 L0 8 L-6 0 Z" transform="translate('+cx+','+cy+')" '+
         'fill="'+FX_COLORS[i%6]+'" style="--dx:'+tx+'px;--dy:'+ty+'px;--rot:'+rot+'deg;--dly:'+(i*22)+'ms"/>';
  }
  return o + '</g>';
}

/* --- 粒子宿主：统一挂载 + 自动回收 --- */
var fxHost = null;
function fxHostEl(){
  if(!fxHost){
    fxHost = document.createElement('div');
    fxHost.className = 'fx-host';
    fxHost.setAttribute('aria-hidden','true');
    (document.getElementById('app') || document.body).appendChild(fxHost);
  }
  return fxHost;
}
/* 通用播放：塞入一段 SVG 片段，播完自己删掉并归还配额 */
function fxPlay(svgText, n, ms){
  if(!fxSpawn(n)) return false;                       /* 超上限：静默放弃 */
  var host = fxHostEl(), box = document.createElement('div');
  box.className = 'fx-box';
  box.innerHTML = svgText;
  host.appendChild(box);
  setTimeout(function(){
    if(box.parentNode){ box.parentNode.removeChild(box); }
    fxKill(n);
  }, ms || 1800);
  return true;
}
```

### 20.6 `prefers-reduced-motion` 降级（可直接粘贴）

```css
/* ===================== §20.6 prefers-reduced-motion 降级 ===================== */
@media (prefers-reduced-motion: reduce){
  /* 所有 infinite 循环一律 animation:none —— 不要把 duration 压成 .001ms，
     那会每帧重启动画 = 高频闪烁，是光敏性风险。 */
  .cloud-a,.cloud-b,.cloud-c,
  .n-locked .lockcloud,
  .n-available .halo,.n-inProgress .halo,.n-available .halo--in,.n-inProgress .halo--in,
  .n-available .disc, .n-inProgress .disc,
  .n-available .flag,.n-inProgress .flag,
  .n-perfect .disc, .n-perfect .crown,
  .n-boss .bossframe,
  .chest3d.is-ready{ animation:none !important; }

  /* 一次性动画：保留"出现/消失"的颜色与透明度变化，去掉位移与缩放 */
  .fx-confetti .cf,
  .fx-starburst .sp,
  .fx-shards .sh,
  .fx-halo{ animation-duration:600ms !important; }

  @keyframes cfall   { 0%{opacity:0;} 20%{opacity:1;} 100%{opacity:0;} }
  @keyframes spburst { 0%{opacity:0;} 25%{opacity:1;} 100%{opacity:0;} }
  @keyframes shburst { 0%{opacity:0;} 25%{opacity:1;} 100%{opacity:0;} }
  @keyframes haloout { 0%{opacity:.9;} 100%{opacity:0;} }

  /* 答错抖动：位移换成"描边闪一下"，保留第 3 通道但不产生位移 */
  .fb-err .ic-fb{ animation:errflash .5s ease-in-out 2 !important; }
  @keyframes errflash{ 0%,100%{stroke:#FFFFFF;} 50%{stroke:#FFD86B;} }
  .shake{ animation:none !important; }
  /* 宝箱开盖：一次性、非循环、非闪烁，保留但放慢 */
  .c-lid{ transition-duration:.32s; }
}
```

**降级为什么这么设计**（三条理由，工程师照做即可）：

1. **`infinite` 循环必须 `animation:none`，不能压缩时长。** 把 `animation-duration` 设成 `.001ms` 是网上的常见"技巧"，但那会让浏览器**每帧重启一次动画**，实际效果是高频闪烁——对光敏性癫痫用户是风险，比原始动画危害更大。
2. **一次性动画只删位移和缩放，保留颜色变化。** 这是 GDD §11.7 的原话。实现上是在 `@media` 里**重定义同名 `@keyframes`**，只写 `opacity`。后定义的同名关键帧在匹配的媒体查询内优先生效。
3. **答错抖动的替代方案是"闪描边"而不是"闪背景"。** 因为背景闪会连带整块卡片亮度跳变，同样有闪烁风险；只改 3px 描边的颜色，亮度变化面积小得多。
