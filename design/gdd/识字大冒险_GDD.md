## 1. 核心循环（MDA）

### 1.1 MDA 三层定义

| 层 | 内容 |
|---|---|
| **M 机制 Mechanics** | 点选（Tap）、翻牌（Flip）、拍击（Whack）、路径选择（Path）、配对（Match）、喂养（Feed）、装扮（Dress） |
| **D 动态 Dynamics** | ① 孩子为「让墨墨长大」重复刷关 → ② 为「第三颗星」重玩已通关关卡 → ③ 为「集齐 100 字图鉴」主动往前推 → ④ 家长侧：为「今天还没学」而打开 App |
| **A 美学 Aesthetics** | **发现**（象形图变形成汉字）/ **收集**（100 字图鉴 + 8 件装扮）/ **陪伴**（宠物需求与情绪）/ **挑战**（三星 + 连击）/ **表达**（装扮宠物、给它起名） |

### 1.2 主循环（5 步闭环）

```
   ┌──────────────────────────────────────────────────────┐
   │                                                      │
   ▼                                                      │
[ACTION] 点地图上的关卡节点（唯一高亮、上下浮动 1.2s 循环）   │
   │                                                      │
   ▼                                                      │
[FEEDBACK] S1 学字：每点「我学会了」→ 印章砸下 + 叮咚 +     │
   │         能量果 +1 飞向顶部计数器（500ms 贝塞尔）        │
   ▼                                                      │
[REWARD] S2 小游戏 ×2 + S3 小考：连击音阶逐级上扬、          │
   │         每局结束 3s 演出、宠物跳出来讨吃的             │
   ▼                                                      │
[PROGRESSION] S4 通关演出 → 三星判定 → 星星/能量果/碎片      │
   │         入账 → 宠物亲密度条上涨 → 图鉴点亮 5 格         │
   │         → 下一关节点解锁 + 地图自动滚到新节点           │
   └──────────────────────────────────────────────────────┘
```

### 1.3 「孩子每 3 分钟在做什么」时间表

> 单关目标总时长 **4.5–6 分钟**；下表为节奏基准（实测需在真机校准，见 §9.4）。

| 累计时间 | 孩子在做什么 | 系统给了什么反馈 |
|---|---|---|
| 0:00–0:05 | 点地图上跳动的关卡节点 | 节点 `scale(1)→1.15` 200ms + `sfx("tap")` + 镜头（scroll）平滑滚到该关 600ms |
| 0:05–0:12 | 关卡详情页：看本关 5 个字的剪影 + 点「出发」 | 5 个字依次从 `opacity 0, translateY(12px)` 淡入（每个错开 80ms）+ TTS 逐个读 |
| 0:12–1:50 | **S1 学 5 个字**（每字 3 步，见 §3.2） | 每字：图→字变形 550ms + TTS ×2 + 组词可点读 + 印章演出 300ms + 能量果飞入 |
| 1:50–1:53 | 学字段落演出：宠物跳出「字都学会啦！」 | 宠物 `translateY(40px)→0` 350ms + 气泡 + `speak()` 台词 |
| 1:53–2:40 | **S2 小游戏 1**（约 45s） | 每答对 +1 能量果 + 连击音阶；全对追加 +3 能量果演出 |
| 2:40–2:43 | 小局结算：能量果飞入 + 宠物可能喊饿 | 3s 微间隔（防止连续高压） |
| 2:43–3:30 | **S2 小游戏 2**（约 45s，不同玩法） | 同上，但题型/感官通道不同（听 → 看 → 动）切换 |
| 3:30–4:25 | **S3 小考 5 题**（每题 ~10s） | 每题即时 600ms 反馈；答错零惩罚（§9.1） |
| 4:25–4:27 | 全屏暗场 + 「字灵考验结束」 | 遮罩 200ms 淡入 |
| 4:27–4:30 | 关卡徽章弹出 + TTS「通关啦！」 | `scale(.3)→1.1→1` 400ms |
| 4:30–4:33 | 彩纸 24 片落下 | 1.2s ease-out |
| 4:33–4:36 | 三星依次落下（间隔 220ms） | 每颗 `translateY(-200px)→0` + `rotate(-180deg)→0` + `sfx("star")` |
| 4:36–4:40 | 资源飞入顶部计数器 | 能量果/碎片错开 150ms，各 400ms |
| 4:40–4:45 | 结算面板淡入 + 宠物亲密度条上涨 | `translateY(20px)→0` 300ms + 进度条 `width` 600ms transition |
| 4:45– | 结算面板：选「下一关 / 再玩一次 / 回地图」 | 下一关节点已在地图上高亮跳动 |

### 1.4 「为什么想再来一次」— 三个留存钩子

> 每个钩子都必须在**结算面板同屏**可见，不允许藏在二级页面。

| 钩子 | 驱动 | UI 呈现（结算面板内） | 触发心理 |
|---|---|---|---|
| **① 收集差一点** | 图鉴 | 「图鉴 45/100」进度条 + 本关新点亮的 5 格翻面动画（500ms） | 蔡格尼克效应：看得见的未完成 |
| **② 宠物差一点** | 陪伴 | 墨墨头像 + 亲密度条 `██████░░░░ 320/500` + 气泡「再陪我玩一会儿，我就要变大啦～」 | 拟社会关系 + 进度可见 |
| **③ 星星差一颗** | 挑战 | 三星显示为 `★★☆`，灰星下方小字「小考全对就能点亮它！」 | 目标梯度效应（离目标越近动力越强） |

**设计约束**：三个钩子**任意时刻最多同时强调 1 个**（结算面板根据当前状态自动选最有效的那个）：

```js
function pickHook(){
  if (justMissedThirdStar())  return "star";    // 差一颗星 → 最强
  if (petBondPct() >= 0.75)   return "pet";     // 宠物快升级
  return "codex";                                // 默认收集
}
```

### 2.3 地图的空间隐喻：**「字灵群岛 · 天空阶梯」**

**选型理由**：
- **纵向滚动**（不是横向）→ 手机/平板上单指上下滑最自然，20 个节点排成一条蜿蜒向上的路径，天然表达「越往上越难」
- 岛屿 + 空中台阶的混合 → 每个区域是一块悬浮岛，岛之间由彩虹桥 / 藤蔓 / 星梯连接，全部可用**参数化 SVG** 表达（`path` 曲线 + 渐变 + 若干装饰图元），零位图
- 不用森林/洞穴等封闭空间（5 岁儿童对"迷路"有焦虑，开阔的天空更安全）

**地图构成（单个 SVG，viewBox `0 0 400 2520`，纵向 4 段）**：

**关卡节点在岛上的蛇形排布**（每区 5 个节点，坐标由公式生成，不手写）：

```js
/* 区域 z(0..3)，区内序号 k(0..4) → 节点中心坐标
   ⚠️ v1.1：新增 7 个前景色字段（dark/line/numBg/numFg/starOut/haloOut/haloIn）
   原因：四区是深色夜空，v1.0 那套「浅底 + 深字」的假设在四区全部失效 */
var LIGHT={dark:false, line:"#3B2A1E", numBg:"#FFFFFF", numFg:"#3B2A1E",
           starOut:"#3B2A1E", haloOut:"#3B2A1E", haloIn:"#FFFFFF"};
var DARK ={dark:true,  line:"#E8E3FF", numBg:"#E8E3FF", numFg:"#2E2A5E",
           starOut:"#FFFFFF", haloOut:"#FFFFFF", haloIn:"#FFE9A8"};
var ZONE_CFG=[
  {name:"青草岛", y0:120,  sky:["#BFE9FF","#E8F7D4"], land:"#7CC576", accent:"#FFB86B", deco:"tree",  f:LIGHT},
  {name:"果园谷", y0:720,  sky:["#FFE3C2","#FFD9EC"], land:"#FFB86B", accent:"#FF8FB1", deco:"fruit", f:LIGHT},
  {name:"云上城", y0:1320, sky:["#D6E4FF","#F0E6FF"], land:"#A9C8FF", accent:"#C9B6FF", deco:"cloud", f:LIGHT},
  {name:"星星堡", y0:1920, sky:["#2E2A5E","#5B4B9E"], land:"#6C5CE7", accent:"#FFD86B", deco:"star",  f:DARK }
];
var MAP_W=400, MAP_H=2520;            // ⚠️ v1.1：2400 → 2520（见 §2.3 修正说明）
function nodePos(levelIndex){          // levelIndex 0..19
  var z=Math.floor(levelIndex/5), k=levelIndex%5;
  var cfg=ZONE_CFG[z];
  var col=(k%2===0)?0:1;               // 左右两列蛇形
  var x = col===0 ? 110 : 290;
  var y = cfg.y0 + 100 + k*104;
  return {x:x, y:y, zone:z, k:k, cfg:cfg, f:cfg.f};
}
function isBoss(levelIndex){ return (levelIndex % 5) === 4; }   // L5/L10/L15/L20
```

#### 状态判定与数据映射（消除与美术规格的字段歧义）

`perfect` 是 `cleared` 的**子集**（`stars===3`），不是并列状态。渲染前必须先归一化：

**`currentLevelIdx` 的定义**（0 基，被 `nodePos(i)` / `nodeRenderState(i)` / `isBoss(i)` 共用，**全文档唯一定义处**）：

```js
/* ⚠️ v1.2 补：v1.0/v1.1 只引用了 currentLevelIdx，没给推导，工程无法落地 */
function currentLevelIdx(){
  return Math.min(19, Math.max(0, (state.game.unlockedThrough|0) - 1));
}
```

- `unlockedThrough` 由 §12.4 的 `recalcZones(s)` 派生：`Math.min(20, maxCleared + 1)`，**不单独存**（避免两份真相不同步）
- 每次写档后调 `recalcZones` → 地图 `currentLevelIdx()` 自动跟着走
- 全通关时 `unlockedThrough=20` → `currentLevelIdx()=19` → L20 命中 `cleared`/`perfect` 分支，不会卡在 `available`

**状态归一化函数**（地图渲染**唯一**的读档入口，不许在别处直接读 `levels`）：

```js
/* 唯一权威数据源：state.game.levels["L1".."L20"]（见 §12.2）
   {stars:0..3, cleared:bool, plays:n, best:n, firstClearAt:ts, sections:0..3}
   ✅ 美术规格 §17.4 已于 v2.0 同步为本形状，两侧一致，无第二套 */
function nodeRenderState(levelIndex){
  var lv = state.game.levels["L"+(levelIndex+1)] || {};
  if(lv.cleared && (lv.stars|0) >= 3) return {state:"perfect",    stars:3,               sections:3};
  if(lv.cleared)                      return {state:"cleared",    stars:lv.stars||1,     sections:3};
  if(levelIndex === currentLevelIdx()){
    var sec = lv.sections || 0;
    return {state: sec>0 ? "inProgress" : "available", stars:0, sections:sec};
  }
  return {state:"locked", stars:0, sections:0};
}
```

**已知边界（不是 bug，别改）**：重玩一个已通关的旧关时，中途退出不会把该关变成 `inProgress`——因为地图只呈现**永久性成就**，`inProgress` 专属于当前推进关。中途退出仍然保存 `sections`（§3.5），回到地图再点进去会接着上次的小节继续，只是节点外观保持 `cleared`。

对应到 §2.4 表格的渲染规则：

| 归一化 state | 星位显示 | 皇冠 | 金边 | 动画 |
|---|---|---|---|---|
| `cleared`（`stars` 1 或 2） | 3 个星位，`stars` 颗亮、其余暗 | ❌ | ❌ | **全部关闭**（已完成的关卡不该继续闪，否则整张地图太吵） |
| `perfect`（`stars` 3） | 3 颗全亮 | ✅ | ✅ 4px + 发光 | 每 3s 只在末尾 0.4s 闪一下 + 皇冠上下浮动 2.4s |

### 2.5 解锁规则（**纯线性，零消耗，不可卡死**）

```
L1                  → 默认解锁
L(n+1)              → 条件：L(n) 且 L(n).stars >= 1
Zone(z+1) 的第一个关 → 条件：Zone(z) 的 L(5z) 通关（即线性，无额外门槛）
```

- **解锁不消耗任何货币**（早期草案曾设计「花星星解锁区域」，已否决：孩子把星星花在装扮上会永久卡关，属于致命挫败设计）
- 区域切换时额外演出：地图自动 `scrollTo` 到新区（800ms smooth）→ 新区 `opacity 0→1` + `translateY(40px)→0` 600ms → 锁图标 `rotate(0)→-30deg` 200ms 后碎成 6 片飞散 400ms → `sfx("unlock")`

### 2.7 终局与长线留存（v1.3 新增）

#### 2.7.1 内容墙的位置

单关 4.5–6 min（Boss 7–9 min），日均 20 min（§9.4 上限）→ 20 关约 **6–8 天纯推进**，计入三星重玩与不每日游玩的实际情况，实测预期 **3–5 周**到达全通关。

#### 2.7.3 终局地图的呈现语义

全通关时 `currentLevelIdx()` 返回 19（L20，已是 `perfect`），**地图上不再有 `available`/`inProgress` 节点**。这不是「进度条走完的空屏」，而是**成就墙**：20 个节点全部三星 + 皇冠。

因此美术侧的正确目标**不是让终局安静，而是让它像一座奖杯陈列室**——见 art-director §17.7 的相位打散（20 个 `perfect` 同相位会像抽搐）。呈现原则：

| 原则 | 说明 |
|---|---|
| ✅ 保留全部 20 个皇冠与金环 | 这是孩子 3–5 周的成果，关掉等于否定他 |
| ⚠️ 相位必须打散 | 同步 = 抽搐，错开 = 星海（art §17.7 ① 的 `-137ms`/`-211ms` 互质步长，已验证 20 个相位唯一） |
| ⚠️ 禁止 `drop-shadow` | 20 个 SVG filter 层在移动端滚动掉帧，用双层同心描边替代（art §17.7 ②） |
| ❌ 不追加「全部完成！」全屏弹层 | 每次进地图都弹 = 骚扰；成就表达已由 20 个皇冠承担 |

**低优先（可延后）**：终局后每 7 天给宠物追加一句新台词（复用 §5.4 台词池，不新增语音文件）。

## 4. 经济系统

### 4.1 设计原则

1. **孩子侧最多 3 种货币 + 1 种凭证**，超出会记不住
2. **星星不可用于解锁关卡**（§2.5 已说明），只用于装扮与成就 → 花光也不会卡关
3. **能量果是高频小额货币**（喂宠物，每天自然消耗），负责「每天都有事做」
4. **钥匙碎片 → 宝箱 → 奖券**，是唯一通向「现实奖励」的路径，且**孩子全程可见**

#### 4.3.1 ⭐ 星星收支核算（v1.3 新增，结论：勉强闭合，不能收紧）

装扮是星星的**唯一消耗出口**（§4.4），集齐 8 件需要 ⭐ 136。一次性来源：

| 来源 | ⭐ | 计算 |
|---|---|---|
| 关卡三星（普通 16 关） | 48 | 16 × 3 |
| 关卡三星（Boss 4 关 ×2 加成） | 24 | 4 × 6 |
| 图鉴里程碑 25/50/75/100 | 20 | 4 × 5 |
| 区域全通 ×4 | 40 | 4 × 10 |
| **一次性小计** | **132** | |
| 每日任务（学满 5 字） | +1/天 | 可重复 |
| 每日字灵挑战（终局后） | +1/天 | 可重复，§2.7.2 |

**缺口 ⭐ 4 → 需 4 天日常补齐**。结论：**当前数值刚好闭合，但没有余量**。

三条红线（改数值前必读）：

1. **不准削减任何星星产出**——136 的 sink 已经贴着 132 的 source，砍一项就是永久缺口。
2. **不准上调装扮价格**——同上，8 件 136 星已是上限。
3. **「学满 5 字」必须含复习**（见上表 ⚠️），否则终局后每日 +1 失效，缺口 4 变成永久缺口，集齐装扮这条收集线**永远无法完成**——这直接击穿 §1 的 Aesthetics「收集」。

> 三条红线里第 3 条是本轮实际存在且未被发现的缺陷：v1.2 及以前只写了「当日学满 5 字」，未定义是否要求新字，工程若按「新字」实现就会静默埋雷。

```js
function gamePool(min){
  var out=[], seen={};
  function add(o){ if(o && !seen[o.c]){ seen[o.c]=1; out.push(o); } }
  /* 1) 当前关卡的 5 个字（最高优先级，保证「学完就考」） */
  levelChars(currentLevel).forEach(add);
  /* 2) 已掌握的字（图鉴 s=2，用于跨关复习，权重最高） */
  Object.keys(state.codex).forEach(function(c){ if(state.codex[c].s===2) add(findCharObj(c)); });
  /* 3) 已解锁未掌握的字（图鉴 s=1） */
  Object.keys(state.codex).forEach(function(c){ if(state.codex[c].s===1) add(findCharObj(c)); });
  /* 4) 兜底：字库前部常用字 */
  for(var i=0;i<CHAR_DICT.length && out.length<min+4;i++) add(CHAR_DICT[i]);
  return out;
}
```

```js
/* 全部音效用振荡器实时合成，零音频文件、零外链 */
var AC=null;
function ac(){
  if(!AC){ try{ AC=new (window.AudioContext||window.webkitAudioContext)(); }catch(e){ return null; } }
  if(AC.state==="suspended") AC.resume();     // iOS 需在用户手势中调用
  return AC;
}
function tone(freq,dur,type,vol,delay){
  var c=ac(); if(!c) return;
  var t0=c.currentTime+(delay||0);
  var o=c.createOscillator(), g=c.createGain();
  o.type=type||"sine"; o.frequency.setValueAtTime(freq,t0);
  g.gain.setValueAtTime(0.0001,t0);
  g.gain.linearRampToValueAtTime(vol==null?0.18:vol, t0+0.015);
  g.gain.exponentialRampToValueAtTime(0.0001, t0+dur/1000);
  o.connect(g); g.connect(c.destination);
  o.start(t0); o.stop(t0+dur/1000+0.03);
}
function sfx(name, combo){
  if(!state.settingsNew || !state.settingsNew.soundOn) return;
  switch(name){
    case "tap":    tone(880,60,"sine",0.08); break;
    case "right":  /* C5-E5-G5 上行三音，连击时整体升 (combo-1) 个半音 */
      var m=Math.pow(2,((combo||1)-1)/12);
      tone(523.25*m,90,"sine",0.18); tone(659.25*m,90,"sine",0.18,80); tone(783.99*m,150,"sine",0.18,160);
      break;
    case "wrong":  /* G4→D#4 下行，音量刻意压低，不刺耳、不构成惩罚感 */
      tone(392,140,"triangle",0.10); tone(311.13,220,"triangle",0.10,130); break;
    case "clear":  [523.25,659.25,783.99,1046.5].forEach(function(f,i){tone(f,160,"sine",0.20,i*120);}); break;
    case "levelup":[440,554.37,659.25,880,1108.73].forEach(function(f,i){tone(f,150,"sine",0.20,i*110);}); break;
    case "unlock": tone(880,100,"sine",0.16); tone(1174.66,200,"sine",0.16,95); break;
    case "chest":  [659.25,783.99,987.77,1318.5].forEach(function(f,i){tone(f,120,"triangle",0.16,i*100);}); break;
    case "star":   tone(1046.5,110,"sine",0.16); tone(1318.5,180,"sine",0.14,100); break;
    case "coin":   tone(1046.5,60,"sine",0.12); tone(1567.98,120,"sine",0.10,55); break;
    case "pop":    tone(1470,45,"sine",0.09); break;

/* 首次任意用户手势时解锁 AudioContext（iOS 自动播放策略） */
```

### 9.3 动态难度下调（**孩子无感知**）

```js
/* 同一关内，连续答错 3 题 → 自动进入 easy 模式（不告知、不提示、不扣分） */
function onWrong(){
  wrongStreak++;
  if(wrongStreak>=3 && !easyMode){
    easyMode=true;
    applyEasy();   // ① 候选数 4→3（移除 1 个最难的干扰项）
                   // ② 反应类游戏停留时长 +400ms
                   // ③ 允许无限次 TTS 重播
                   // ④ 免费提示额度 +2
  }
}
function onRight(){ wrongStreak=0; }   // 答对即清零（但不退出 easy 模式，本关保持）
```

## 12. 数据模型变更与迁移方案

### 12.1 设计原则

1. **append-only**：学习记录（`learned` / `codex` / `stats` / `chest.log` / `coupons`）只追加，不删除
2. **只增不改**：v1 的所有字段**一个都不删、一个都不改语义**（云端已有真实数据）
3. **向后兼容**：v1 数据能无损升级到 v2；v2 数据的「设置」字段始终包含完整 v2 快照，即使云端建表失败也不丢
4. **幂等**：迁移函数可重复调用，多次调用结果一致

### 12.4 迁移函数（v1 → v2，幂等）

```js
function migrate(s){
  if(!s || typeof s !== "object") return defaultStateV2();
  if(s.version >= 2) return normalizeV2(s);      // 已迁移，只做补齐

  /* ── 步骤 0：补齐 v1 应有可能缺失的字段（防御历史脏数据）── */
  var d = defaultStateV2();
  for(var k in d){ if(!(k in s)) s[k] = d[k]; }
  if(!s.settings || typeof s.settings !== "object") s.settings = {dailyCount:5};
  if(!s.learned  || typeof s.learned  !== "object") s.learned  = {};
  if(!Array.isArray(s.stagesCleared)) s.stagesCleared = [];

  /* ── 步骤 1：learned → codex（已学字 = 已解锁，绝不能丢）── */
  s.codex = {};
  for(var ch in s.learned){
    if(!s.learned.hasOwnProperty(ch)) continue;
    var dd = s.learned[ch];
    s.codex[ch] = {
      s: 1,                                                   // 1=已解锁
      right: 0, wrong: 0,
      firstAt: Date.parse(dd && dd.date) || Date.now(),
      masterAt: null
    };
  }
  var learnedN = Object.keys(s.codex).length;

  /* ── 步骤 2：v1 积分 → 星星 / 能量果（让孩子升级后立刻有资源可用）── */
  s.starsTotal = Math.floor(s.points / 10);
  s.stars      = s.starsTotal;
  s.energy     = Math.min(999, Math.floor(s.points / 2));
  s.shards     = 0;
  s.keys       = 0;

  /* ── 步骤 3：v1 的 10 关制 stagesCleared → v2 的 20 关制 game.levels ──
     v1 第 k 关（0-based）的积分门槛是 STAGE_THRESH[k]，对应 v2 的 L(2k+1) 与 L(2k+2) */
  s.game = {levels:{}, zones:[0,0,0,0], lastPlayedLevel:null, unlockedThrough:1};
  for(var k2 = 0; k2 < s.stagesCleared.length; k2++){
    var idx = s.stagesCleared[k2];
    if(typeof idx !== "number" || idx < 0 || idx >= 10) continue;
    ["L"+(2*idx+1), "L"+(2*idx+2)].forEach(function(lid){
      var n = parseInt(lid.slice(1), 10);
      if(n >= 1 && n <= 20){
        s.game.levels[lid] = {stars:1, cleared:true, plays:1, best:0,
                              firstClearAt: s.updatedAt || Date.now(), migrated:true};
      }
    });
  }
  recalcZones(s);     // 从 levels 派生 zones 与 unlockedThrough

  /* ── 步骤 4：v1 redeemed → coupons（标记为已核销，避免孩子重复领现实奖励）── */
  s.coupons = [];
  for(var rid in s.redeemed){
    if(!s.redeemed.hasOwnProperty(rid)) continue;
    var rw = null;
    for(var i2 = 0; i2 < s.rewards.length; i2++) if(s.rewards[i2].id === rid) rw = s.rewards[i2];
    s.coupons.push({
      id: "mig_" + rid,
      rewardId: rid,
      name: rw ? rw.name : "已兑换奖励",
      gotAt: s.updatedAt || Date.now(),
      redeemedAt: s.updatedAt || Date.now(),     // 老数据视为已核销
      code: "MIGRATED",
      migrated: true
    });
  }

  /* ── 步骤 5：宠物初始亲密度按已学字数给（老用户不该从蛋重新开始）── */
  s.pet = {
    name:"墨墨", species:"ink",
    bond: Math.min(490, learnedN * 5),           // 已学 100 字 → 490（接近 Lv5）
    level: 1,                                     // 下面立即重算
    fedToday:0, petToday:0, lastCareDate:"",
    wears:{hat:null,scarf:null,wing:null,bg:null},
    owned:[], mood:"happy", friends:[]
  };
  s.pet.level = bondToLevel(s.pet.bond);

  /* ── 步骤 6：补齐其余 v2 默认值 ── */
  s.chest = {opened:0, log:[]};
  s.daily = {};
  s.streak = {cur: streakV1(), best: streakV1(), lastDate: todayStr()};   // 用 v1 的 streak() 算一次并固化
  s.stats = {totalRight: s.quizRight || 0, totalWrong: 0, playSeconds: 0, sessions: 0, wrongByChar: {}};
  s.settingsNew = {
    dailyMinutes:20, restReminder:true, soundOn:true,
    chestPool: buildDefaultChestPool(s.rewards)    // 默认把现有 3 个奖励全部放入奖池
  };

  /* ── 步骤 7：v1 的 cursor / dayStart / startDate 原样保留 ──
     （家长中心的「今日应学 N 字」统计仍在用，不删） */

  s.version = 2;
  return normalizeV2(s);
}

function buildDefaultChestPool(rewards){
  var pool = {};
  (rewards||[]).forEach(function(r){
    pool[r.id] = {inPool:true, needCoupons:1, dailyLimit:1};
  });
  return pool;
}

function recalcZones(s){
  var z=[0,0,0,0], maxCleared=0;
  for(var n=1;n<=20;n++){
    var L = s.game.levels["L"+n];
    if(L && L.cleared){ z[Math.floor((n-1)/5)]++; if(n>maxCleared) maxCleared=n; }
  }
  s.game.zones = z;
  s.game.unlockedThrough = Math.min(20, maxCleared+1);
}

/* 幂等补齐：任何字段缺失都补默认值，可重复调用 */
function normalizeV2(s){
  var d = defaultStateV2();
  for(var k in d){ if(!(k in s) || s[k]===null || s[k]===undefined) s[k]=d[k]; }
  if(!s.game) s.game = d.game;
  if(!s.game.levels) s.game.levels = {};
  if(!Array.isArray(s.game.zones) || s.game.zones.length!==4) s.game.zones=[0,0,0,0];
  if(!s.pet) s.pet = d.pet;
```

```js
function ensureDaily(){
  var t = todayStr();
  if(!state.daily[t]){
    state.daily[t] = {login:true, firstClear:false, learnCount:0, playCount:0, petLines:[], energyEarned:0};

      grantLoginReward(state.streak.cur);    // 登录奖励 + 连续天数档位奖励

  }
  /* 宠物每日计数跨日重置 */

    state.pet.fedToday = 0;
```

## 13. `data-page-node-id` 标注体系（工程约束）

### 13.1 规则

1. **每个可见元素**必须带 `data-page-node-id`，格式：**22 位大小写字母 + 数字**（与现有文件一致，如 `mNHRC8Fk9WpLyAsJ9MzlTi`）
2. **ID 必须稳定**：动态渲染的元素（关卡节点、图鉴格、宠物部件、小游戏选项）**不能用随机数**，必须由元素的语义 key 确定性派生，否则每次渲染 ID 都变，资料库导入会 diff 失败
3. 现有文件里**已有的** ID 全部保留，不改动

### 13.2 动态元素 ID 生成（推荐实现）

```js
/* 由元素语义名确定性派生 22 位 base62 ID：同一元素每次渲染结果一致 */
var NID_ALPHABET = "0123456789abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ";
var _nidCache = {};
function nid(semanticName){
  if(_nidCache[semanticName]) return _nidCache[semanticName];
  /* FNV-1a 32bit */
  var h = 2166136261, s = "shiziV2|" + semanticName;
  for(var i=0;i<s.length;i++){ h ^= s.charCodeAt(i); h = Math.imul(h, 16777619) >>> 0; }
  /* 展开成 22 位 base62：每轮用 h 的不同位段，避免尾部重复 */
  var out = "";
  for(var k=0;k<22;k++){
    out += NID_ALPHABET[(h + Math.imul(h, 31) + Math.imul(k, 7919)) % 62];
    h = (h >>> 3) ^ (Math.imul(h, 2654435761) >>> 0);
    h >>>= 0;
  }
  _nidCache[semanticName] = out;
  return out;
}
```

| 图鉴格 | `codex.cell.日` | `nid("codex.cell."+ch)` |
