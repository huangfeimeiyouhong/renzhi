### 1.2 三个代码级发现（写实现规格前必须知道）

#### 发现 #1（P0，最高优先级）— 光环 / 星轨 / 王冠在 Lv7+ 已溢出可视区

`petSVG` 的缩放写法（`:3466`）：
```
<g class="pk-all" transform="translate(60,120) scale(S) translate(-60,-120)">
```
即「以 (60,120) 为中心放大 S 倍」。变换后坐标 `p' = S*(p − (60,120)) + (60,120)`。

按此换算（`viewBox="-15 11 150 150"`，`.pet-slot .pet` 占舞台 82% 且 `overflow:visible`，`.pet-stage` 为 `overflow:hidden`，故实际可视上边界约在 viewBox y ≈ **−5.5**）：

| 元素 | 未缩放 y | Lv5 (S=1.30) | Lv10 (S=1.65) | Lv20 (S=1.75) |
|---|---|---|---|---|
| 光环 `cy=30` | 30 | 3.0 ✅ 勉强可见 | −28.5 ❌ | −37.5 ❌ |
| 星轨 `translate(60,28)` | 28 | 0.4 ✅ 勉强可见 | −31.8 ❌ | −41.0 ❌ |
| 王冠尖 `translate(60,42)−13` | 29 | 1.7 ✅ | −30.3 ❌ | −39.3 ❌ |
| 身体顶 `cy=84, ry=33` | 51 | 30.3 ✅ | 6.1 ✅ | −0.75 ⚠️ 贴边 |
| 脚下阴影 `cy=124` | 124 | 125.2 ✅ | 126.6 ✅ | 127.0 ✅ |

**结论：约 Lv7 起（S > 1.39）光环与星轨就飞出画面了，Lv10 起王冠也飞出去了。**
这直接决定了 Lv21+ 的设计：**不能靠继续放大，也不能指望"把光环做大"——因为光环现在根本看不见。**

> ⚠️ 请工程侧（程基岩）在浏览器里目视复核 Lv10 / Lv20 的宠物页：光环（头顶虚线椭圆）和 5 颗字灵星轨还在不在画面内。若复核结果与上表不符，以实测为准并回我。

**最小修复建议（改动小、可独立排期，见 §5.3）**：把 `.pk-halo` / `.pk-aura` / `.pk-satellites` 三个 `<g>` **从 `pk-all` 移到 `pk-all` 之外**，改用不受 scale 影响的「画面坐标」，半径随等级派生。

#### 发现 #2 — `line` 字段对 Lv5+ 是死数据

`:3456–3457`：
```js
var lineC = (lv >= 5) ? '#FFC93C' : S.line;
```
Lv5–Lv20 表里填的 `#FFC93C / #FFD86B / #FFE08A / …` **全部不生效**，描边恒定 `#FFC93C`。
→ 本设计仍会给出 `line` 列（保持 8 字段结构完整 + 为将来启用留口），但**不要指望它产生色彩变化**。真正的颜色变化由 `theme` / `hi` / `belly` 承担。

#### 发现 #3 — 「10 次抚摸上限」硬编码在 2 处，改数值时必须同步

- `:3763` `if(s.pet.petToday >= 10)` — 逻辑拦截
- `:3816` `Math.max(0,(10-(state.pet.petToday||0)))` — 宠物页提示文案「今天还能摸 N 次」

改产出时若只改一处，会出现「还能摸 10 次但点了没反应」的 bug。

### 1.3 既存曲线瑕疵（顺带记录，本次不动）

`PET_BOND_THRESH` 的级间增量：
`50,100,150,200,250,300,350,400,450,` **300**,`300,300,300,300,300,300,300,300,300`

Lv9→Lv10 是 **+450**，Lv10→Lv11 反而掉到 **+300** — 增量非单调，孩子会感觉「到了 10 级突然变快又变慢」。
本设计的 Lv21+ 增量（250 → 200）正好接上这条下降线，理由是**后期用「边际成本递减」对冲疲劳感**（见 §3.5）。Lv11–Lv20 的 +300 **本次不动**，避免影响已有存档体验。

### 2.3 命名说明

- 全部为「墨墨·XX」，20 个互不重复，且与 Lv1–Lv20 的 20 个名字**无一重复**。
- 语义与配色轨道严格对应：
  - **Lv21–26 星空段**（淡紫）：星辰 → 星海 → 银河 → 宇宙 → 幻彩 → 紫霞
  - **Lv27–32 霞凤段**（粉 → 珊瑚）：彩虹 → 彩云 → 霞光 → 彩凤 → 飞凤 → 火凤
  - **Lv33–40 金阙段**（桃 → 杏 → 正金）：金凤 → 金龙 → 龙凤 → 朝阳 → 金辉 → 金冠 → 天王 → **至尊**
- **字难度**：`辰 / 宙 / 幻 / 霞 / 凤 / 辉 / 冠 / 至 / 尊` 超出 5 岁认读范围（其余均为常用字）。两个处理方向，请家长拍板（第 8 节 D4）：
  - (a) 保留 —— 家长陪读，且「认宠物名」本身就是识字素材；
  - (b) 把宠物名里的字**纳入图鉴**（推荐，见 §5.5），让它们变成"下次要学的字"。

### 2.4 配色说明

- 生成方式：HSL 色相从 Lv20 的 **251°（淡紫）沿 360° 方向旋转 154° 到 45°（正金）**，途经 紫 → 紫罗兰 → 藕粉 → 珊瑚 → 蜜桃 → 杏 → 金。饱和度 70%→100%（尾段才明显提饱和，保证中段是马卡龙粉而非荧光粉），明度带单调性约束。
- **明度实测**：204 → 236（整体递增）。但 Lv28–Lv35 因色相走「粉/桃」会有约 1.5% 的轻微平台（215 → 208 → 回升），**视觉上读作"粉得更浓"而非"变暗"**，且同期光环/星轨在变大，整体仍读作"越来越亮"。
- 全部落在既有色域家族内（与 `#FFE9A8 / #FFD86B / #FFF6DF / #BCADFF` 同源），**不引入新的高饱和色**，符合儿童低饱和马卡龙 palette。
- ⚠️ 再次提醒：`line` 列对 Lv5+ 不生效（发现 #2），表中列出只为字段完整；如要让描边也走金色渐变，需改 `:3457`（见 §5.3 可选增强）。

### 3.6 方案对比与推荐

| 维度 | BASE | A | B | **C** |
|---|---|---|---|---|
| 满级（典型档） | 1.23 年 ❌ | 1.07 年 ⚠️ | 7.4 月 | **7.1 月** ✅ |
| 典型档每级耗时 | 12.0 天 ❌ | 8–10 天 ⚠️ | 6.0 天 | **4.4–5.6 天** ✅ |
| 曲线上限可控 | ❌ | ⚠️（喂食仍无上限） | ❌ 完全失控 | ✅ 快档封顶 ~65/日 |
| 宠物成长绑定"学字" | ❌ | ❌ | ❌ | ✅（C-2） |
| 改动量 | 0 | 仅数据表 | 3 处数值 | 数据表 + 3 处数值 + 1 个新挂点 |

**→ 推荐方案 C。理由：**
1. **每级 ≈ 一周**（典型 5 天）是 5 岁孩子的耐心阈值——一周至少看到一次"墨墨变了"，且中间还有称号/装扮填充。
2. **全程 7.1 个月**，既够长（长期有奔头）又不至于让孩子在懂事之前都摸不到顶。
3. C-2 是唯一一个能同时解决「节奏」和「设计错位」的改动：**让"我今天学了 5 个字"直接变成"墨墨长大了"**，这正是陪伴系统该有的因果链。
4. 后期边际成本递减（250 → 200）**对冲疲劳感**：玩了半年的孩子日产会自然上涨（关卡打得多 → 能量果多），用递减阈值把它拉回 5 天/级的节奏。

## 5. Lv21+ 视觉成长方案（替代 scale 放大）

### 5.1 三条通道

| 通道 | 承担什么 | 是否新增数据 |
|---|---|---|
| ① 配色走金 | 最大的视觉面积（身体径向渐变） | 已在 `PET_STAGES.theme/hi/belly` 里 |
| ② 光环 / 星轨 / 外发光半径派生 | "变更强"的体积感 | **否**，由 `lv` 派生 |
| ③ 装扮 / 背景 / 称号 | 具体的"我今天拿到了什么" | 见 §4 |

### 5.2 派生参数表（**由 `lv` 计算，不进数据表** — 保证 `PET_STAGES` 与 `PET_BOND_THRESH` 严格 1:1）

```js
/* 在 petSVG() 内计算。k = lv-20，Lv20 时为 0，Lv40 时为 20 */
var k = Math.max(0, lv - 20);
var haloRx  = 24 + k * 0.60;    /* Lv20: 24.0 → Lv40: 36.0  (+50%) */
var haloRy  = 7.5 + k * 0.16;   /* Lv20: 7.5  → Lv40: 10.7 */
var auraR   = 52 + k * 0.40;    /* Lv20: 52   → Lv40: 60    (见下方警告) */
var glowOp  = 0.55 + k * 0.008; /* Lv20: .55  → Lv40: .71 */
var orbitN  = (lv >= 25) ? 7 : 5;              /* Lv25 起 5 → 7 颗 */
var orbitR  = (lv >= 25) ? 5.8 : 7;            /* 星点半径，点数变多则变小 */
var orbFill = (lv >= 35) ? '#FFF6DF' : '#FFE9A8';
var orbLine = (lv >= 35) ? '#D69A1E' : '#B87400';
var haloW   = (lv >= 35) ? 4.2 : 3.4;          /* 光环描边加粗 */
```

> ⚠️ **`auraR` 只从 52 加到 60，不是加到 76**。原因：`.pk-aura` 现在位于 `pk-all` 内部，会被 `scale(1.75)` 二次放大，实际表观半径 = `auraR × 1.75`。52 → 表观 91，60 → 表观 **105**（+15%）。若直接写 76，表观 133 会明显过曝、糊住整个舞台。**这是"写数据的人看不到实际渲染"的典型陷阱，请工程侧务必按表观值验收。**

### 5.3 光环 / 星轨修复（发现 #1 的落地方案，建议与 Lv21+ 同批做）

**推荐做法**：把 `.pk-halo` / `.pk-aura` / `.pk-satellites` 三个 `<g>` **移出 `pk-all`**，改用不受 scale 影响的画面坐标：

```js
/* 放在 pk-all 之前（底层）或之后（顶层），坐标不再乘 scale */
var haloCy = 44;                                  /* 固定，不再被 scale 推走 */
out += '<ellipse cx="60" cy="'+haloCy+'" rx="'+haloRx+'" ry="'+haloRy+'" … />';
out += '<circle cx="60" cy="88" r="'+auraR+'" class="pk-aura" … />';
/* 星轨中心固定在 (60,46)，星点绕行半径 R = 30 + k*0.5 */
```
- 收益：Lv4–Lv40 **全部等级都能看见**光环和星轨，且 Lv21+ 的"变大"真正可见。
- 成本：需要重新目视调 `haloCy` / 星轨中心，避免与王冠、耳朵、帽子重叠（Lv5 戴帽子时头顶空间紧张）。
- 排期建议：**独立一个小任务**，先用 Lv5 / Lv10 / Lv20 三个等级截图对比，确认不再溢出后再上 Lv21+。

**备选（更保守，可不改结构）**：光环/星轨维持现状（高等级看不见），Lv21+ 的成长感只靠**配色 + 装扮 + 金色粒子**。成本最低但成长感偏弱，且"花了 8 件美术却只换了个颜色"。

**可选增强（让 `line` 列活过来）**：把 `:3457` 改为
```js
var lineC = S.accent || (lv >= 5 ? '#FFC93C' : S.line);
```
并给 Lv21+ 追加 `accent` 字段（取表中 `line` 列的值）。描边/王冠/尾迹会跟着走金渐变，成长感更强。`accent` 是 append-only 字段，不影响 40 项对应关系。

### 5.4 地图上的小宠物（新增约束）

`:2889` 地图用的是 `<svg x="-24" y="-56" width="48" height="56" viewBox="0 0 120 140" overflow="visible">` 内嵌同一只宠物（缩放系数约 0.32）。
**放大后的光环/星轨在地图上必然溢出节点板**。建议：`petSVG` 增加 `opt.compact`（地图传 `true`），`compact` 时**不渲染 halo / aura / satellites**，只画本体 + 配色 + 已装备的装扮。既避免糊，也顺带省移动端性能。

### 5.5 附加设计建议：宠物名即识字素材

把 Lv1–40 全部 40 个宠物名 + 20 个称号用到的汉字做成一个"宠物名字表"，**纳入图鉴的待学字池**（或至少在宠物页点击名字能读出该字）。
- 收益：宠物系统从"消耗内容的奖励层"变成"识字内容的一部分"，家长接受度显著提升。
- 成本：低（一个静态数组 + 复用现有图鉴详情弹窗）。
- 优先级：P1，请家长拍板。
